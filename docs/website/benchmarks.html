How fast is Branch Network?

Branch Network is the compiled networking layer of Branch. You declare events on your services, and the Branch Studio plugin writes the serialisation code for them. We raced it against the two best-known libraries of its kind: same schemas, same data, same machine.

See the benchmark code on GitHub →

Summary

Every case below, merged into one view. “X% faster” means the other library needs X% more time than Branch for the same work: if Branch takes 1.0 ms and NetRay 1.5 ms, Branch is 50% faster.

Branch was faster in every case but one: the function round trip is a tie, because the network decides it, not the code. Branch also sends the same or fewer bytes everywhere, and it validates everything a client sends. NetRay does not by default.

Part 1 · Lune

The generated code alone, outside Roblox: clean, repeatable numbers for comparing the code itself.

  • Same generated code. Each library's code came from its own compiler and the same schema: the Blink CLI, the NetRay CLI and Branch Studio.
  • Fake Roblox. The code ran in Lune (a Luau runtime) inside a small fake Roblox: players, RemoteEvents and a frame clock. One fake server and N fake clients passed real buffers to each other.
  • Measured: encode is every Fire call plus the end-of-frame flush; decode is receiving and dispatching; total is both.
  • Runs: 30 warm-up and 300 measured frames, 5 repeats (best kept), and the whole benchmark 3 times (best cell kept).
  • Units: milliseconds per frame, lower is better. Branch's numbers include server-side validation.

Part 2 · Roblox Studio

The real engine: a Play session in Studio with a real server and a real client.

  • One place, three libraries. A benchmark place with all three libraries side by side, each with the same schema.
  • NetRay's own method. The harness follows the NetRay author's benchmark place: same car data, 50 sends per frame. We added the flush time, remote calls, server → client sends, and decode timed on a real captured packet.
  • Equal instrumentation. All three libraries were measured the same way.
  • Units: nanoseconds per message, lower is better.
