Branch.Network

The code Branch Studio generates from your Service.Network declarations. Every event and function gets its own typed functions, so autocomplete shows the exact arguments.

Branch.Network.Server.<Service>.<Event>   -- on the server
Branch.Network.Client.<Service>.<Event>   -- on a client
Branch.Network.OnReject                    -- on the server

In the signatures below, ...args stands for the arguments your Data declares: nothing, one value, a tuple, a struct table, or the struct's fields with Unpack. See Declare.

When it works:

  • Using Server on a client, or Client on the server, is an error.
  • Outside a running game (plugins, the command bar), every call does nothing.

Server → client events

Declared with From = "Server". Used from the server; received on clients.

Event.Fire server

Server.Service.Event.Fire(player: Player, ...args)

Sends to one player. Batched with that player's other events this frame.

Event.FireAll server

Server.Service.Event.FireAll(...args)

Sends to every player. The frame's broadcasts go out once, through FireAllClients, and each player still receives everything in order.

Event.FireList server

Server.Service.Event.FireList(players: { Player }, ...args)

Sends to each player in the list.

Event.FireExcept server

Server.Service.Event.FireExcept(except: Player, ...args)

Sends to every player but one.

Event.On client

Client.Service.Event.On(listener: (...args) -> ()): () -> ()

Listens for the event. Returns a function that disconnects the listener. Events that arrived before the first listener are queued and delivered to it.

Client → server events

Declared with From = "Client". Used from a client; received on the server.

Event.Fire client

Client.Service.Event.Fire(...args)

Sends to the server, batched with the client's other events this frame.

Event.On server

Server.Service.Event.On(listener: (player: Player, ...args) -> ()): () -> ()

Listens for the event. player is who sent it, and every argument has already been validated against your declaration. Returns a function that disconnects the listener.

Functions

Declared with a Return. A client asks, the server answers.

Function.Invoke client · yields

Client.Service.Function.Invoke(...args): ...returns

Sends the request at once (it does not wait for the end of the frame) and yields for the answer. Raises an error if the server's handler errored, or if the request could not be queued on the server.

Function.On server

Server.Service.Function.On(handler: (player: Player, ...args) -> ...returns)

Sets the one handler for the function. Setting it again replaces the old one. Requests that arrived before the handler was set are answered once it is.

Rejected packets

Branch.Network.OnReject server

Branch.Network.OnReject(handler: (player: Player, reason: string) -> ()): () -> ()

Called when a client sends a packet that fails validation: wrong sizes, out-of-range values, NaN, wrong Instance classes, forged lengths or oversized packets. The packet is dropped either way. Use it to log or kick exploiters. Returns a function that removes the handler.

Branch.Network.OnReject(function(player, reason)
	warn(`{player.Name}: {reason}`)
end)

Listener modes

CallHow listeners run
"Async" (default)Each call runs in a pooled thread, so a listener may yield freely.
"Sync"Listeners run inline, in the receive loop: the fastest option. A listener that yields does not corrupt later events, and one that errors is reported without dropping the rest of the packet.
