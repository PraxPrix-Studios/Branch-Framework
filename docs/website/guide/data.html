guide/data

Player data

Branch.Data keeps each player's data in ProfileStore (through DataService) and mirrors it to their client. You describe the data once, as a template, and Branch refuses any write that does not fit it.

Start it once

-- server, e.g. in PlayerService:Init
local Data = Branch.Data.Server

Data.Start({
	Template = {
		coins = 0,
		stats = { kills = 0, best = 0 },
		items = {},                       -- an array
		friends = {},                     -- a dictionary (e.g. by UserId)
	},
	Store = "PlayerData",                -- ProfileStore name (this is the default)
	Mock = game:GetService("RunService"):IsStudio(),
	Leaderstats = { "coins" },
	Migrations = {},
})

Every option is described in the API reference. With Branch Studio, keep the template in its own ModuleScript and point Settings → Paths → Data template at it: you get autocomplete for every path.

Paths

You read and write with dot paths: "coins", "stats.kills", "items.3.id". They are parsed once and cached.

  • Numbers in a path. A numeric part indexes an array. In a dictionary it reaches the string key, so "friends.12345" works for UserId-keyed maps. Writing into an empty table, 1 starts an array and any other number starts a dictionary (an array cannot start at 12345), so a table never mixes number and string keys, which DataStores refuse to save.
  • Before the data loads. Reads return nil. Writes raise an error that tells you to wait with Data.Await(player) or Data.OnLoaded.
local Data = Branch.Data.Server

Data.Get(player, "stats.kills")              -- nil until loaded
Data.Set(player, "coins", 5)
Data.Increment(player, "coins")              -- +1, returns the new value
Data.Increment(player, "coins", -3)
Data.Update(player, "stats.best", function(old) return math.max(old, 10) end)
Data.Insert(player, "items", { id = 7 })     -- append (or pass an index to insert there)
Data.Remove(player, "items", 1)              -- returns the removed value

What Branch refuses

  • Values that do not fit the template. Checks go all the way down: a nested table with a missing key or a wrong type is refused. If an array in the template holds an element, Insert checks new elements against it.
  • NaN and infinity, in any write, including nested tables. DataStores cannot store them, and a single one (a division by zero, say) would make every later save of the profile fail.

A refused write raises an error at your call, so the bug shows up where it happened, not later in a broken save.

Array elements in the template are real data. ProfileStore copies the template into every new profile. With items = { { id = 0 } }, Insert checks new items against { id = 0 }, but every new player also starts with that item in their array. Use it only when that item is a real starting item; otherwise keep the array empty (items = {}). An empty array is not shape-checked on Insert, but NaN and infinity still are.

Reacting to changes

local stop = Data.Observe(player, "coins", function(new, old)
	print("coins:", old, "->", new)
end)
-- later: stop()

Data.OnLoaded(function(player, data)
	-- every player whose data is already loaded, then each new one
end)

local data = Data.Await(player) -- yields; nil if they leave first

Observe runs once straight away (once the data is loaded) and after every change. It also fires when a parent table is replaced: Set(player, "stats", {...}) reaches observers of "stats.kills".

On the client

Branch.Data.Client is a read-only mirror of the local player's data. It starts syncing as soon as it is required; there is nothing to start.

local Data = Branch.Data.Client

Data.Observe("coins", function(coins) label.Text = coins end)
Data.OnInserted("items", function(index, item) end)
Data.OnRemoved("items", function(index, item) end)
local data = Data.Await()

If the server never calls Data.Start, the client warns after 15 seconds instead of waiting silently.

Leaderstats

Leaderstats = { "coins", "stats.kills" }               -- names: "coins", "kills"
Leaderstats = { coins = "Coins", ["stats.kills"] = "Kills" } -- path = display name
  • Value types. Numbers use NumberValue, so fractions are never cut off. Booleans use BoolValue, everything else StringValue.
  • Your own leaderstats. If the game already made a value with the same name and class, Branch drives that one instead of adding a duplicate.

Migrations

When the shape of your data changes, add a migration. Migrations[n] upgrades a profile from version n-1 to n:

Migrations = {
	function(data) data.stats.best = data.stats.best or 0 end,   -- v0 -> v1
	function(data) data.coins = data.coins * 10 end,            -- v1 -> v2: coins are worth less now
}
  • When they run. Migrations run right after the profile loads, before the client ever sees the data.
  • New profiles. A brand-new profile already has the newest shape, so no migrations run on it.
  • New keys are already there. Fields the template gained are filled in before migrations run, so a migration that moves coins into a new wallet.coins finds wallet already made, holding the template's default.
  • Updates rolling out. Old servers keep running for a while after you publish. An old server (fewer migrations) that loads an already upgraded profile leaves its version alone, so no migration ever runs twice.
  • Failures. Migrations run on a copy. If one fails, the saved data is left exactly as it was, the error names the migration, and the player is asked to rejoin. Data is never saved half-upgraded.
Only append. Never edit or reorder a migration that already shipped: profiles remember which version they reached.

Branch Studio reminds you. When you point Settings → Paths → Data template at your template, removing a field or changing its type shows a warning under Problems until you confirm the migration is written. New fields need no migration: old saves get them automatically.

When a player leaves

Segments' PlayerRemoving hooks can still read and write the leaving player's data. The profile is released on the next resumption point, after every leave handler has run, and those writes are saved with the session. Write before your hook yields (task.wait, web calls).

Offline players and messages

local saved = Data.Peek(userId)                       -- read an offline player's data (yields)
Data.Send(userId, "Gift", { "sword" })                -- delivered when they are online
Data.OnMessage("Gift", function(player, payload) ... end)
Data.Reset(player)                                    -- wipe the profile and kick
local profile = Data.GetProfile(player)               -- the raw profile, if you need it
