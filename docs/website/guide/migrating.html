Moving from Branch 1

Branch 2 is a rewrite. Most games move over in an afternoon: the loader call changes, utilities move, and DataService becomes Branch.Data.

What changed

Branch 1Branch 2
Branch:StartSegments(folder) / StartSegmentsDeep(folder)Branch:Start(folder, ...)
Every nested ModuleScript was a segmentModules named …Service / …Controller are segments. With "Folders", only modules reached through Folders are.
Packages.Branch.Scythe / ThreadReaper / TimerPackages.Branch.Util.Scythe / ThreadReaper / Timer
A separate Packages.DataServiceBranch.Data.Server / Branch.Data.Client
-- BRANCH_EXPORTS block-- BRANCH_GENERATED block, managed by Branch Studio

Steps

  1. Update the runtime. Open Branch Studio and press Update on the Overview page. The plugin never touches a Branch 1 runtime before you do.
  2. Change the start calls to Branch:Start(...) on the server and the client.
  3. Check your segment names. With the default "Suffix" rule, services must end in Service and controllers in Controller. Branch Studio warns about modules that have Init or Start but no suffix. If you would rather keep your folder layout, pick the "Folders" rule.
  4. Fix utility requires: require(Packages.Branch.Util.Timer) and so on.
  5. Move player data to Branch.Data.Server.Start. Keep the store your saves are in: Branch 1's DataService used the store "Public" unless you passed another profileStoreIndex, while Branch.Data defaults to "PlayerData". So pass Store = "Public" (or your old name), or every player starts from scratch. The key prefix, "PLAYER_", is the same. Then remove the old DataService copies.
  6. Press Play. Branch:GetReport() shows every segment and its status.

What you get for free

  • The Timer from Branch 1 is fixed:
    • a pause no longer counts as elapsed time;
    • IncrementTime keeps the queue in order;
    • Stop wakes threads waiting in Wait;
    • callbacks never run twice, and a callback that errors cannot break other timers.
  • A helper nested inside a segment is no longer started as a segment of its own.
  • DataService no longer holds a player's session lock when they leave during loading.
