Branch Studio

The free Studio plugin that does the busywork: it installs and updates the runtime, compiles typed autocomplete and networking while you type, finds mistakes before you press Play, shows what your game does while it runs, and lets you browse and edit DataStores.

Toolbar

ButtonWhat it does
BranchOpens the Branch Studio window.
CompileCompiles types and networking now.
LiveTurns compiling while you edit on or off.

What it does for you

  • Compiles as you type. After you pause, the plugin rebuilds typed autocomplete (GetSegment, data paths) and Branch.Network. All outputs land in one undo step, and nothing is written when nothing changed.
  • Segment names as you type. Inside the quotes of Branch:GetSegment("…") or a LocateSegments({ "…" }) list, the script editor suggests your segments: services in server scripts, controllers in client scripts, both in shared modules. It does not depend on the type compiler, so it works with either Luau type solver.
  • Feature switches clean up after themselves. Turning Network off deletes Branch.Network and resets its type. Turning it back on regenerates everything. The same goes for Types and Data types.
  • Templates for new modules. A new segment module is filled from the Service or Controller template, with {NAME} replaced by the module's name. The plugin waits for Studio's own local module = {} return module to land first, so the template is never overwritten. A module renamed to …Service or …Controller while still empty is filled too.
  • Smart rename. Renaming a module carries the new name into your code, in one undo step:
    • the module's own table name, in code only (strings, comments and fields such as data.Shop keep their text);
    • lookups by name in every script: GetSegment("Shop"), LocateSegments, Dependencies;
    • paths that reach the module, relative or absolute: script.Util, script.Parent.Shop.Util, :WaitForChild("Shop"), game.ReplicatedStorage.Shared.Util, workspace.Map. Only paths that really lead to that module change.
    Casing tools (PascalCase, camelCase, snake_case, SNAKE_CASE or your own prefix) rename everything the same way and never give two segments the same name.
  • Safe install and update. The plugin remembers which runtime files it installed, with a fingerprint of each. On update, files that are no longer shipped are removed, and files you edited by hand are copied to ServerStorage.BranchBackups before they are replaced. Your generated files and settings are kept. A Branch 1 runtime is never touched until you press Update.
  • Branch (live) while you Play. One window with the game's traffic, every Init time and players' data. See Branch (live).
  • Smaller types in one click. Press Profile on the Network page, play, then press Finish on the Network tab of Branch (live). The hints appear under Problems; clicking one changes that type in your declaration (one undo step) and compiles again. See Apply the hints with one click.
  • Live DataStores are read-only. Browsing real data is safe by default. To edit, save, restore a version or delete, click the lock twice: that allows writes to live data until Studio closes. Try sample stays editable.
  • Data template warnings. The plugin remembers your data template's shape. If a field is removed or changes type (a number becoming a string, say), saved player data will not follow on its own, so a warning in Problems asks for a migration; click it once the migration is written. New fields need nothing: ProfileStore adds them to old saves.
  • Honest renames. References the rename could not update safely — a path through a variable, a chain split across lines — are listed in the Log, with a click to open each one.
  • Checks engine names. A mistyped Enum(...) is an error (the last working network stays), and an unknown Instance(...) class is a warning.
  • Light on slow machines.
    • Modules are re-read only when their text changed, and networking is regenerated only when a declaration or a network setting changed.
    • The wait before a compile grows on slower machines, and only ModuleScripts wake the plugin.
    • Lite mode (Settings › Appearance) turns off animations, gradients, see-through panels and the background, and keeps only the open page in memory.
  • Stays out of the way. It does nothing in Play mode, and every connection is cleaned up when it unloads.

Health checks

Every compile also looks for mistakes that would otherwise show up only in a running game. They appear under Problems on the Overview page; click one to open the script at that line. Nothing is run: the checks read your code.

KindWhat it finds
errorDependency cycle. A depends on B and B on A (directly or through others): there is no valid order for their Init.
warningA lookup at the top of a module. Branch:GetSegment("X") outside any function runs while segments are still loading, so it works only if X happened to load first. Look segments up in :Init() or later.
warningA segment used in Init before its own Init ran. ShopService:Init uses InventoryService, whose Init runs later: add it to Dependencies.
warningA dependency that is not a segment, or one from the other side (a service depending on a controller).
warningWaitForChild without a timeout in Init. If the child never appears, Init never ends and every segment after it waits.
hintAn event nobody uses: declared but never sent, or sent but never listened to (.On). Strings and comments do not count as uses.
hintDelta with a Key and no Forget anywhere in your code. Fine when the keys are a fixed set (200 mobs that respawn with the same ids); when new objects get new keys, every key ever sent stays in memory. Not shown for Keys with only a few possible values (u8, enums, ranges up to 1000).
hintClient input without limits (security): client events and functions without Rate, and client-sent strings, buffers or arrays without a maximum length.

Segments page

The Segments page lists services, then controllers, in the order Branch runs their Init: dependencies first, then the order they were found. Each row shows the segment's number in that order, what it needs (its Dependencies and the segments it looks up with GetSegment) and which segments use it. Segments in a cycle are red. The real time each Init took is on the Startup tab of Branch (live).

Branch (live)

While you Play in Studio, Branch Studio opens one window, Branch (live), with three tabs. It only exists in Studio: nothing of it reaches a published game.

TabWhat it shows
NetworkEvery event in both directions: sends per second, bytes per second and share of the traffic, busiest first. Hints for numbers that could travel smaller (for example "always a whole number from 0 to 200: declare it as u8 instead of u32"). A switch at the top turns the counters off or on for this Play (off: nothing is counted, zero cost). In a profiling session, Finish. See Profile.
StartupHow long each segment's Init took, on the server and on your client, in the order they ran. A bar shows which one is slow; a failed Init is red. Init runs one segment at a time, so a slow one delays everything after it.
DataEvery player whose Branch.Data has loaded, and their data as a tree. Click a value to change it: the change goes through Data.Set, so the template checks it like any write, and the game and the player see it at once.

Turn the window off in Settings → Editor → Live window. The traffic counters have their own switch: Profiler on the Network page (the same as Settings → Editor → Network profiler). When either is off, the counters do not run at all.

Test migrations

Before you ship a new migration, try it on a real save. On the DataStores page, open a player's key and press Test migrations (the arrow button next to Versions). Studio starts Play for a moment, your game's own Migrations run on a copy of that save, and you see what the player would get: the result as a read-only tree, and either "the result fits the template" or the migration that failed and why. Nothing is written, and the result cannot be restored over the save. The same works on Try sample.

Appearance

Settings › Appearance changes how the plugin looks. It is yours alone (saved with your Studio, never in the place), and a friend can take your look with a theme code.

PartWhat you can change
ThemeAuto (follows Studio's light or dark theme), Midnight, Daylight, Graphite, Frost, Ember, Aurora (a gradient with light glass panels), Rose, High contrast. Every theme is checked for readable text.
BackgroundNone, a color, a gradient (up to 6 colors, an angle, an optional very slow drift) or a picture. For a picture: paste its id, or select an ImageLabel, ImageButton or Decal in the Explorer and press Use selected (a Decal id is turned into its image id). Then Blur, Dim, Tint (your accent over it), Fit (Fill, Fit, Tile), Focus (which part stays in view), Keep text readable (a bright picture is dimmed a little more), Match colors to picture and your last five backgrounds. Glass sets how much shows through the panels, Edge shade darkens the top and bottom.
ColorsThe 8 main colors, or all 18, each with a color picker and a way back to the theme's own. Copy theme gives a one-line code of letters and digits (BT1-…: colors and background; a picture goes by its id), Paste theme takes one.
LayoutDensity (Compact, Comfortable), Corners (Sharp, Soft, Round), Text size (S, M, L).
PerformanceLite mode for slower computers, and Animations on or off.

Pictures you uploaded (you or your group) get a real blur, Focus and Match colors: Roblox lets plugins read only those. Any other picture still works as a background, with a lighter blur made of a few shifted copies, and the page says so. The blur is made once when you let go of the slider, so it costs nothing while you work; moving Dim or Tint never rebuilds the pages.

Community, roles and unlocks

  • My themes (Settings › Appearance): save the current look in a slot and switch back in one click. 2 slots are free; slots 3 to 8 are a game pass each.
  • Image backgrounds are a game pass. Colors, gradients and every theme stay free. Without the pass an image background (yours or from a theme code) shows as no background.
  • Unlock lists every pass with its price and a link to copy (plugins cannot open the Roblox purchase prompt in Studio). Buy it on roblox.com: while the panel is open the plugin checks every few seconds, so it unlocks right away. Ownership always comes from Roblox.
  • Roles: Owner, Tester and VIP. Every role has everything unlocked and can add a profile background. A role shows next to the name; users without one show no badge.
  • Community page: how many games use Branch (the games on published profiles), the games built with Branch, the people with roles, and search for any Roblox username. A profile card shows the avatar, role, theme (with Try this theme) and games.
  • My profile: show your current theme, add the published experience open in Studio, and (with a role) a background. Only owners publish, so press Copy profile code (BP1-…) and send it to an owner. Profiles have no free text: names come from Roblox and pictures are Roblox images.
  • Roles and profiles live in community/community.json in the public Branch-Framework repository. Owners change them from the Admin panel with their own GitHub token (fine-grained, that repository only, Contents: read and write), which stays on their computer. Everyone reads the file without a token; changes reach everyone within a few minutes.

Settings code

Your own settings (the look and the Editor tab) are kept per Roblox account on each computer: Roblox has no cloud sync for plugin settings. To take them to another computer or place, use the Settings code card at the bottom of the Settings page (every tab).

  • Copy settings code puts every setting in one line of letters and digits (BS1-…), selected for Ctrl+C: your look and editor settings, and this place's project and network settings. Only what differs from the defaults goes in, so it stays short.
  • Paste settings code, Enter, then choose what to apply: My settings (only you), This place's settings (for everyone working in this place), or both. Everything the code does not mention goes back to its default, so you get exactly what was copied.
  • Last codes: the last 5 codes you copied, each with when and the place it came from, for example 27 Sep 17:24 (Arena). Copy one again or apply it.
  • A code is the settings themselves, not a key to something stored elsewhere: different settings never share a code. The last two characters are a check (CRC-10), so a changed, missing or extra character is reported as a damaged code and never applied.

Automation

Code with plugin permissions can drive the plugin by setting the widget attribute BranchCommand to tab:<page>, compile, install, sample, expandAll, profile (start a profiling session), hint:<n> (apply the n-th type hint), migrateSample (test migrations on the sample profile), look:<theme code> (apply a theme code), appearance:<json> (the whole appearance, lite mode included), section:<tab> (a Settings tab: Appearance, Project, Network, Editor), copySettings / offerSettings / applySettings (the Settings code card's steps), profile:<userId> (open a profile card), unlock (the Unlock panel) or complete (the segment-name suggestions for the open script's cursor, written to the widget's BranchCompleteResult attribute). While you Play, the Branch (live) widget's BranchLiveTab attribute picks a tab (Network, Startup, Data).
