Anticheat

Branch protects its network in three layers: the server's rules for every request, an anticheat that watches each client, and an optional strict mode. On top of that you pick the checks your game needs, add your own, and decide what happens to a player: a kick, a report, a score that grows until it acts.

The three layers

LayerWhat it stopsCostDefault
Server rulesMalformed and forged packets, spam, requests that break your Cooldown, Alive, Near, Owned rules, packets made for another gameAlmost noneAlways on
AnticheatTampered clients, remote spies repeating calls, killed heartbeats; the movement checks you turn on; your own checks~4 bytes/s per player, nothing per sendOn
Strict modeCopied, repeated and hand-made packets (refused before any listener), sends from code that is not your game's8 bytes per client packet, ~0.09 µs per sendOff

All three are switched in Branch Studio, Settings › Network: Anticheat, Strict mode, and Kick after forged packets (0 means nobody is ever kicked, only reported). Everything else is code, through Branch.Network.Anticheat.

What no anticheat can promise. An exploit runs inside the player's own client, so a determined exploiter can take any client-side check apart. This one stops scripts made for other games and pasted cheats, and makes every update of your game cost the cheat's author work. What makes cheating pointless is the server deciding results: clients send what they want to do, the server checks it.

Branch's own checks

Always on with the anticheat. Every client sends a small signed heartbeat every 5 seconds and checks its own network module. A player is flagged only for what a real client never does, so lag, slow devices and scripts in Actors are never mistaken for cheating.

CheckFlagged when
heartbeata heartbeat is forged or sent again, or a player runs more than 64 copies of the client module
silence600 reliable packets arrive in a row without a heartbeat: the heartbeat was switched off while the game still sends
rawthe server got more packets than the client's module sent: a remote spy or a script firing the remote directly
tampera table of the network module was unfrozen, or one of its functions (or one of your checks) was swapped or hooked
strictstrict mode refused sends that no script of the game made

Ready-made checks

Movement checks, off until you turn them on: a racing game wants speed, a pet simulator may want none. They run on the server, so a cheat cannot switch them off. The server looks at every character twice a second, a few per frame.

local Anticheat = Branch.Network.Anticheat

Anticheat.Use("speed")                      -- the Humanoid's WalkSpeed is the limit
Anticheat.Use("teleport", { distance = 80 })
Anticheat.Use("fly", { height = 20, time = 4 })
Anticheat.Use("noclip")
Anticheat.Use("fly", false)                 -- off again
CheckFlagged whenOptions (defaults)
speedfaster than allowed, three samples in a row (1.5 s; a lag burst is one or two)max studs/s (0: the Humanoid's WalkSpeed), tolerance 1.75; allowed = max × tolerance + 4
teleportone jump far beyond walking, even when the server sees it spread over two samplesdistance 100 studs
flyno ground within height below, and not coming down, for time secondsheight 16, time 4
noclipthe path between two samples goes through something solid, three times within 10 s (once or twice can be doors)none
  • Left alone: a character in its first 3 seconds, seated, dead, on PlatformStand or anchored, and one a script of your game just moved (PivotTo, setting the CFrame): the game's own teleports are never findings.
  • Your game moves a player in other ways (a dash, a launch pad, a glider): Anticheat.Pause(player, seconds).
  • By default each of them kicks at a player's fourth finding. The defaults leave room for lag and odd physics, while real cheats stay far beyond them: speed hacks run 2 to 5 times too fast, teleports cover hundreds of studs, flying has no time limit. Their names are taken: call your own checks something else.

Your own checks

Add what only your game knows about: impossible stats, a menu that should not open, a weapon used too fast.

On the client

local Anticheat = Branch.Network.Anticheat

-- runs every 5 s (or every `every` seconds); return a reason, or true, when something is wrong
local stop = Anticheat.Check("gravity", function()
	return workspace.Gravity ~= 196.2 and `Gravity {workspace.Gravity}`
end, 2)

stop() -- takes the check away

-- something your code just saw: sent on the next frame
Anticheat.Report("menu", "admin menu opened")
  • The report cannot be dropped. A finding rides the signed heartbeat, so a cheat that blocks it breaks the heartbeat too. A check that gets hooked counts as tamper.
  • A name is taken once. A second Check with the same name errors, so a cheat cannot swap your check for one that never finds anything. Only the function Check returned can take it away.
  • Checks never hold the game up. Each runs in its own thread at the start of a frame; one that errors is reported in Studio, one that waits is skipped until it returns. every is 1 second or more.
  • The client only says what it found. What happens to the player is decided on the server.

On the server

-- your server checks go the same way as everything else
if coins - lastCoins > 10000 then
	Branch.Network.Anticheat.Flag(player, "coins", `+{coins - lastCoins} in one second`)
end

What happens to a player

Every finding is kept in the player's record, reported to Anticheat.OnFlag(player, check, detail, score) and to Branch.Network.OnReject (as anticheat: check: detail), and then acts in two ways: through its check's action, and through the player's score. Kicks never happen in Studio (a warning instead) or with Kick after forged packets at 0.

Basic or Advanced

PresetHow it decides
"Basic" (default)Each check acts on its own: Branch's checks and yours kick at once, the ready-made ones at the fourth finding, strict only reports. No levels.
"Advanced"Checks only report; the score decides: restricted at 5, kicked at 10, and the score goes down by 1 a minute, so a few lag findings over an hour add up to nothing.
Anticheat.Preset("Advanced") -- then change any part of it below

Actions per check

Anticheat.SetAction("coins", "kick", 3)  -- kick at the third finding; the first two only report
Anticheat.SetAction("menu", "report")    -- never kick, just tell OnFlag
Anticheat.SetAction("raw", "report")     -- Branch's own checks too
Anticheat.SetAction("noise", "ignore")   -- not even recorded
Anticheat.SetKickMessage("Exploits are not allowed here.")

Score and levels

Each finding adds its check's weight to the player's score. Levels act once each, when the score first reaches them.

Anticheat.SetWeight("coins", 4)           -- default 1 for your checks
Anticheat.SetLevel(5, "restrict")
Anticheat.SetLevel(8, function(player, record)
	Webhook:Send(`{player.Name} reached {record.score}`)
end)
Anticheat.SetLevel(12, "kick")
Anticheat.SetDecay(0.5)                   -- points forgotten per minute (0: never)
Default weightChecks
10heartbeat, silence, raw, tamper: one is proof
3teleport, fly
2speed, noclip
1strict and your own checks

Restricted players

A level or Anticheat.Restrict(player) restricts a player without kicking: every request of theirs the server refuses (a bad value, a rate limit, a broken guard) counts as forged, and their rate limits refill at a quarter of the speed. Anticheat.IsRestricted(player) lets your own code be stricter too; Restrict(player, false) lifts it.

Admin panels

Branch keeps a record for every player with a finding, while they are in the server. There is no panel to install: these calls give your own panel what it needs.

local Anticheat = Branch.Network.Anticheat

Anticheat.GetFlagged()             -- every flagged player in the server, highest score first
Anticheat.GetRecord(player)        -- one player's record, or nil
Anticheat.OnChanged(function(player, record)
	-- a finding, a pardon, a restriction; record is nil when the player is gone (pardoned or left)
end)
Anticheat.Pardon(player, "speed")  -- forgive one check: its findings and its score
Anticheat.Pardon(player)           -- forgive everything
Anticheat.Restrict(player)         -- or Restrict(player, false)

A record is a frozen copy, so nothing a panel does reaches the anticheat:

{
	player = Player,
	score = 7,
	restricted = true,
	checks = { speed = { count = 2, detail = "41 studs/s, 28 allowed", at = 1760000000 } },
	history = { { check = "speed", detail = "...", at = 1760000000 }, ... }, -- the last 50
}

To show it to moderators, send it with an event of your own:

ModerationService.Network = {
	Flagged = { From = "Server", Data = { name = "string", score = "f32", checks = "{ [string]: u16 }" } },
}

Anticheat.OnChanged(function(player, record)
	local checks = {}
	for name, entry in record and record.checks or {} do
		checks[name] = entry.count
	end
	Net.Flagged.FireList(moderators, { name = player.Name, score = record and record.score or 0, checks = checks })
end)

Across servers

One line makes every server of your game share its flagged players, so a panel shows them all, live:

Anticheat.ShareAcrossServers(true)    -- on every server, at start

Anticheat.GetFlaggedGlobal()          -- this server's flagged players and every other server's
Anticheat.OnGlobalChanged(function(userId, entry)
	-- entry: { userId, name, score, restricted, checks = { [check] = count }, server, placeId, here }
	-- nil when the player is gone: they left, were pardoned, or their server closed
end)
  • Light on Roblox's limits. Each server publishes only what changed, at most every 3 seconds, in messages under 1 KB on one MessagingService topic. Everything again once a minute, and at once (within 2 s) for a server that just started.
  • Nothing left behind. An entry goes when its server says so, or after 2.5 minutes without a word from a server that crashed. ShareAcrossServers(false) stops it and the other servers forget this one's players.
  • Needs a published game, as MessagingService does. In Studio the list holds the server's own players.

Strict mode

Off by default; turn it on when a game is a common target.

  • Tagged packets. Every client packet starts with an 8-byte tag signed with a key of your place and the player. A copied, repeated or hand-made packet is refused before any listener sees it and counts as forged.
  • Sends only from your scripts. Fire, Invoke and Forget work only when one of your game's scripts made the call. An executor's own code or the command bar is refused, Studio warns once per event, and the heartbeat reports it as strict.
  • One rule for your code: call a send from a function in your script. task.spawn(Net.Hit.Fire, …) or Connect(Net.Hit.Fire) has no script behind it and is refused; wrap it in a function.
button.Activated:Connect(function()
	Net.Hit.Fire(target) -- fine: your function makes the call
end)

Event ids

Every event travels as a number. The first compile in a place picks a random number for each event, spread over the whole range rather than 1, 2, 3, and Branch Studio keeps the list in the place (an attribute of ServerStorage: players never get it, and everyone in Team Create shares it). The heartbeat takes its number from the same list.

  • Other games' scripts do not fit. A packet or script made for another Branch game lands on numbers this place never uses. The server treats it as forged and kicks after Kick after forged packets of them (3 by default). A "works in every Branch game" cheat cannot exist.
  • The keys come from the ids. The heartbeat and strict mode's tags are signed with a key made from this list, so it is your place's own as well.
  • Free: nothing to change in your code, and no cost at run time.

New ids

Settings › Network › New ids gives every event a new number and the keys change with them.

  • When: a cheat that sends ready-made packets shows up in your game, or simply with each big update.
  • Then publish. Players on the new version use the new numbers; a cheat built for the old ones stops fitting. Servers already running keep the old version until their players rejoin, which is fine: each server and its clients always match.
  • Undo: Ctrl+Z puts the old list back, as long as you have not published.
A speed bump, not a wall. The numbers are in the client's code, so a cheat's author can read them again after every New ids. And they do nothing against an exploit that calls your own Fire: that is what strict mode and the server's rules are for.

API

-- client
Anticheat.Check(name, check, every?) -> stop    -- a check of your own
Anticheat.Report(check, detail?)                -- a finding right now
-- server: checks
Anticheat.Use(name, options? | false)           -- "speed" | "teleport" | "fly" | "noclip"
Anticheat.Pause(player, seconds)                -- your game moves them itself
Anticheat.Flag(player, check, detail?)          -- a finding of your server code
-- server: what happens
Anticheat.Preset("Basic" | "Advanced")
Anticheat.SetAction(check, action, after?)      -- "kick" | "report" | "ignore"
Anticheat.SetWeight(check, weight)
Anticheat.SetLevel(at, "restrict" | "kick" | fn | nil)
Anticheat.SetDecay(perMinute)
Anticheat.SetKickMessage(message)
Anticheat.Restrict(player, on?) / IsRestricted(player)
-- server: admin panels
Anticheat.OnFlag(fn(player, check, detail, score)) -> disconnect
Anticheat.OnChanged(fn(player, record?)) -> disconnect
Anticheat.GetFlagged() / GetRecord(player) / Pardon(player, check?)
Anticheat.ShareAcrossServers(on?)
Anticheat.GetFlaggedGlobal() / OnGlobalChanged(fn(userId, entry?)) -> disconnect
