Tutorial: a horde of 200 mobs

The server moves 200 mobs and sends them to every player. Sent the plain way, that is 176 KB of traffic a second. Four words in one declaration bring it to 10 KB/s. Every number on this page was measured.

Download the finished game (.rbxl) The first tutorial
How the numbers were measured: 200 mobs (some walking, the rest resting), one player standing in the middle, 10 seconds at 60 frames a second. The finished game shows 10.6 KB/s in Branch Studio's live profiler in Studio.

1. The game, the plain way

A service keeps 200 mobs. Each walks to a random spot near its home, rests a few seconds, and walks again; resting mobs bob a little, like they breathe. Every frame, the server sends each mob's state to everyone:

Services/HordeService 
local RunService = game:GetService("RunService")
local Branch = require(game.ReplicatedStorage.Packages.Branch)

local HordeService = {}

HordeService.Network = {
	Mob = { From = "Server", Data = { id = "u16", pos = "vector", hp = "u8(0..100)" } },
	Hit = { From = "Client", Rate = "5/s", Data = "u16" }, -- a player hits mob #id
}

local COUNT = 200
local SPEED = 8 -- studs per second

type Mob = { id: number, pos: Vector3, home: Vector3, target: Vector3?, rest: number, hp: number }
local mobs: { Mob } = {}

local function spot(around: Vector3, radius: number): Vector3
	return around + Vector3.new(math.random(-radius, radius), 0, math.random(-radius, radius))
end

function HordeService:Init()
	for id = 1, COUNT do
		local home = spot(Vector3.new(0, 2, 0), 220)
		mobs[id] = { id = id, pos = home, home = home, target = nil, rest = math.random() * 3, hp = 100 }
	end
end

function HordeService:Start()
	local Net = Branch.Network.Server.HordeService
	local clock = 0

	-- players hit mobs; the server decides if the hit counts
	Net.Hit.On(function(player, id)
		local mob = mobs[id]
		local root = player.Character and player.Character:FindFirstChild("HumanoidRootPart")
		if mob and root and (root.Position - mob.pos).Magnitude <= 12 then
			mob.hp = math.max(mob.hp - 25, 0)
			if mob.hp == 0 then
				mob.hp = 100
				mob.pos = spot(mob.home, 40) -- it comes back somewhere else
			end
		end
	end)
	Branch.Network.OnReject(function(player, reason)
		warn(`{player.Name}: {reason}`) -- too many hits, forged packets
	end)

	RunService.Heartbeat:Connect(function(dt)
		clock += dt
		for _, mob in mobs do
			if mob.target then
				local offset = mob.target - mob.pos
				if offset.Magnitude <= SPEED * dt then
					mob.pos, mob.target, mob.rest = mob.target, nil, 2 + math.random() * 3
				else
					mob.pos += offset.Unit * SPEED * dt
				end
			else
				mob.rest -= dt
				if mob.rest <= 0 then
					mob.target = spot(mob.home, 40)
				end
			end
			-- resting mobs still breathe a little
			local shown = mob.pos + Vector3.new(0, math.sin(clock * 2 + mob.id) * 0.05, 0)
			Net.Mob.FireAll({ id = mob.id, pos = shown, hp = mob.hp })
		end
	end)
end

return HordeService

The client draws a part for each mob and glides it to the newest position, so updates can come less often without looking choppy:

Controllers/HordeController 
local Players = game:GetService("Players")
local RunService = game:GetService("RunService")
local UserInputService = game:GetService("UserInputService")
local Branch = require(game.ReplicatedStorage.Packages.Branch)

local HordeController = {}

type View = { part: BasePart, target: Vector3 }

function HordeController:Start()
	local Net = Branch.Network.Client.HordeService
	local folder = Instance.new("Folder")
	folder.Name = "Mobs"
	folder.Parent = workspace
	local views: { [number]: View } = {}

	-- the server sends states; the client draws a part per mob
	Net.Mob.On(function(mob)
		local view = views[mob.id]
		if not view then
			local part = Instance.new("Part")
			part.Name = tostring(mob.id)
			part.Size = Vector3.new(3, 3, 3)
			part.Anchored = true
			part.CanCollide = false
			part.Position = mob.pos
			part.Parent = folder
			view = { part = part, target = mob.pos }
			views[mob.id] = view
		end
		view.target = mob.pos
		view.part.Color = Color3.fromRGB(255, 70, 70):Lerp(Color3.fromRGB(80, 220, 120), mob.hp / 100)
	end)

	-- glide between updates, so 4 or 20 updates a second still look smooth
	RunService.RenderStepped:Connect(function(dt)
		local alpha = math.min(dt * 10, 1)
		for _, view in views do
			view.part.Position = view.part.Position:Lerp(view.target, alpha)
		end
	end)

	-- click a mob to hit it
	local mouse = Players.LocalPlayer:GetMouse()
	UserInputService.InputBegan:Connect(function(input, busy)
		if not busy and input.UserInputType == Enum.UserInputType.MouseButton1 then
			local target = mouse.Target
			if target and target.Parent == folder then
				Net.Hit.Fire(tonumber(target.Name) :: number)
			end
		end
	end)
end

return HordeController
176 KB/sto every player. 200 mobs × 60 frames = 12,000 mob updates a second.

2. Send only what changed: Delta

Delta sends a mob in full once, then only the fields that changed. Key = "id" gives every mob its own state, so one event carries all 200:

Mob = { From = "Server", Delta = true, Key = "id", Data = { id = "u16", pos = "vector", hp = "u8(0..100)" } },
188 KB/sa little more than before.

Why? Every mob breathes, so its position changes every frame, and Delta sends it every frame, plus a byte saying what changed. Delta can only save what does not change. That is the next step.

3. Ignore tiny moves: Threshold

Mob = { From = "Server", Delta = true, Key = "id", Threshold = { pos = 0.1 }, Data = { id = "u16", pos = "vector", hp = "u8(0..100)" } },
115 KB/s−39% from the start. Resting mobs now cost almost nothing: their breathing never moves them 0.1 studs.

The receiver is never more than 0.1 studs off, and small moves add up: a mob that drifts slowly is sent as soon as it has moved 0.1 studs in total. Threshold

4. Fewer updates a second: Hz

Mob = { From = "Server", Delta = true, Key = "id", Threshold = { pos = 0.1 }, Hz = 20, Data = { id = "u16", pos = "vector", hp = "u8(0..100)" } },
40 KB/sthe newest state of each mob goes out 20 times a second instead of 60. The client's gliding hides the difference.

5. Far mobs update rarely: Lod

A mob 200 studs away does not need 20 updates a second. Lod sets the rate by distance, and one line of code changes: FireAll becomes FireFrom, from where the mob is.

Mob = {
	From = "Server",
	Delta = true, -- only what changed
	Key = "id", -- each mob keeps its own state
	Hz = 20, -- the newest state, 20 times a second
	Threshold = { pos = 0.1 }, -- ignore moves under 0.1 studs
	Lod = { { 80, 20 }, { 250, 4 } }, -- near: 20/s, far: 4/s, beyond: nothing
	Data = { id = "u16", pos = "vector", hp = "u8(0..100)" },
},
Net.Mob.FireFrom(mob.pos, { id = mob.id, pos = shown, hp = mob.hp })   -- was: Net.Mob.FireAll({ ... })
10.3 KB/swithin 80 studs: 20 updates a second; up to 250 studs: 4; further away, nothing.

Bonus: hits that cannot be cheated

The finished game lets you click a mob to hit it. The declaration and the server's check:

Hit = { From = "Client", Rate = "5/s", Data = "u16" }, -- a player hits mob #id
-- players hit mobs; the server decides if the hit counts
Net.Hit.On(function(player, id)
	local mob = mobs[id]
	local root = player.Character and player.Character:FindFirstChild("HumanoidRootPart")
	if mob and root and (root.Position - mob.pos).Magnitude <= 12 then
		mob.hp = math.max(mob.hp - 25, 0)
		if mob.hp == 0 then
			mob.hp = 100
			mob.pos = spot(mob.home, 40) -- it comes back somewhere else
		end
	end
end)
  • Rate = "5/s": an auto-clicker sending 100 hits a second gets 5 through; OnReject logs the rest.
  • The server checks the distance: a hit from across the map does nothing.
  • hp = "u8(0..100)": a declared range. Anything a client could send outside it is refused before your code runs.

One more thing the profiler found: id never goes above 200, so u8 would do instead of u16. Try Profile on Branch Studio's Network page and apply it with one click. Apply the hints
