Unique features

Branch is a compiler-driven framework with its own Studio environment. Because the compiler understands your whole project, Branch can do things a plain library cannot. Here is everything that sets it apart.

Networking comes from Branch Studio, the free Studio plugin: it writes Branch.Network from your declarations. Features marked needs Branch Studio work once it is installed; the rest is in the runtime alone.

Networking you declare, compiled for you needs Branch Studio

Declared inside your services

No separate IDL files, no command-line build. The network contract lives next to the code that owns it, in Service.Network, and compiles as you type.

Faster than Blink and NetRay

Measured in Lune and in the real engine: Branch wins every case except the function round trip, which ties. See the benchmarks.

See the numbers →

Stepped numbers

Declare the precision you need and the number shrinks to fit it: f32(0..1, 0.01) travels in 1 byte instead of 4.

How to use →

Runs

When the same event repeats, its id is written once for the whole run instead of once per event.

How to use →

Packed booleans across the whole struct

Every boolean and every "is this optional value here" flag in a record shares one bit mask; boolean arrays pack 8 per byte.

How to use →

One FireAllClients per frame

Broadcasts are written once and shipped once, and every player still receives all events in exact order, even when broadcasts and single sends are mixed.

How to use →

Unreliable, batched safely

Unreliable events are grouped into packets that always stay under Roblox's size limit, instead of one remote call per event.

How to use →

Errors that stay contained

A bad argument errors at your call without corrupting the frame. A listener that throws is reported like any script error, and the rest of the packet still arrives.

Send less needs Branch Studio

Latestnew

Fire a position three times in a frame, and only the newest one is sent. With a Key, the newest value of every object is kept.

Pos = { From = "Server", Latest = true, Data = "vector" }
How to use →

Hznew

Fire every frame, send 20 times a second: the newest value goes out on a timer, and the last one is never lost. A third of the traffic, with no code change.

Stamina = { From = "Server", Hz = 20, Data = "u8" }
How to use →

Lodnew

Near players get a mob 30 times a second, far ones 5 times, and nobody beyond the last ring. One call sends to everyone at the right rate.

Net.Mob.FireFrom(mob.Position, data)
How to use →

Deltanew

Only the fields that changed since the last send travel; a character standing still costs almost nothing. With Key, one event carries many objects, each with its own state.

Unit = { From = "Server", Delta = true, Key = "id", Data = { id = "u16", pos = "vector", hp = "u8" } }
How to use →

Thresholdnew

Positions that jitter by a fraction of a stud are not sent. Small moves add up, so the receiver is never further off than the threshold.

Threshold = { pos = 0.05 }
How to use →

Booleans that cost zero bytesnew

In a Delta event, a changed boolean is not sent at all: its "changed" bit already says it flipped.

How to use →

Packnew

Small numbers, enums and booleans are written as bits, not bytes. A 200-item inventory goes from 1,000 bytes to about 500.

Bag = { From = "Server", Pack = true, Data = "{ id: u16(0..1000), count: u8(0..99) }[]" }
How to use →

FireNearnew

Send only to players whose character is within a radius. In a big map, the savings grow with the player count.

Net.Explosion.FireNear(position, 150, damage)

Security built into the declaration needs Branch Studio

Everything from clients is validated

Bounds, ranges, NaN and infinity, enum values, Instance classes and array lengths are checked on the server before any listener runs. Lengths are checked before anything is allocated.

How to use →

Rate limitsnew

One word stops exploiters spamming valid events. Extra events are dropped, functions answer "failed", and OnReject tells you who.

Attack = { From = "Client", Rate = "10/s", Data = { dir = "vector" } }
How to use →

Server code never reaches playersnew

The generated server half lives in ServerScriptService: players do not download it, and exploiters cannot read the server's checks.

How to use →

OnReject

One place to hear about every malformed packet and every rate-limit breach, to log or kick.

A Studio environment, not just a library needs Branch Studio

Live compiler

Typed autocomplete for your segments and data paths, and the network code, rebuilt as you type, in one undo step. Nothing is written when nothing changed.

How to use →

Bytes per fire, before you run

The Network page shows every event's direction, reliability and wire size while you write it.

How to use →

Live network profilernew

While you Play, a window shows every event's sends per second, bytes per second and share of the traffic, busiest first. Studio only: zero cost in live servers.

How to use →

Smaller types in one clicknew

Profile a Play session and Branch Studio lists every number that could travel smaller ("always 0 to 200: u8 instead of u32 saves 3 B per value"). One click changes the declaration.

How to use →

Smart rename

Rename a module and its name follows through your code: the table name, GetSegment, Dependencies, and every path that really leads to it. What it cannot update safely, it lists for you.

How to use →

Engine names checked while you type

A mistyped Enum(...) is an error and an unknown Instance(...) class is a warning, before the game ever runs.

How to use →

Templates for new modules

New services and controllers start from your own template, and Studio's default text never overwrites it.

How to use →

Safe install and update

Updating the runtime removes files that are no longer shipped and backs up any file you edited by hand before replacing it.

How to use →

Light on slow machines

Only changed modules are re-read, the network is only rebuilt when its declarations change, the wait before compiling adapts to the computer, and animations can be turned off.

How to use →

Player data that cannot be corrupted

Template checks all the way down

Every write is checked against your template, including nested tables, so a typo or a wrong type never reaches a save.

How to use →

No NaN, no infinity

A division by zero cannot break a profile: values DataStores cannot store are refused at the write.

How to use →

Migrations on a copy

If a migration fails halfway, the saved data is left untouched and the player is asked to rejoin. Data is never saved half-upgraded.

How to use →

Template change warningsnew

needs Branch Studio

Remove a field or change its type, and Branch Studio warns that saved data will not follow on its own, until you add a migration.

How to use →

Writes on the way out

PlayerRemoving hooks can still change the leaving player's data, and those writes are saved with the session.

How to use →

Observers that see everything

Observe("stats.kills") fires even when the whole stats table is replaced, and "friends.12345" reaches UserId-keyed dictionaries.

How to use →

A DataStore browser that protects players

needs Branch Studio

Browse stores as a fast virtual tree, restore old versions, watch the 4 MB limit. ProfileStore session locks are respected, a player's newer progress is never overwritten, and live data is read-only until you unlock writes.

How to use →

A framework that stays out of your way

Segments by name

Any module named …Service or …Controller, at any depth and in any casing, is a segment. Everything else is a helper. Services can live inside services.

How to use →

A strict, readable lifecycle

Init in dependency order, then every Start in its own thread, then player and frame hooks sharing one engine connection per hook type.

How to use →

Failures you can see

A slow Init warns after 5 seconds, a failed dependency is named, two segments with one name are an error, and Branch.Netwrok fails loudly instead of returning nil.
