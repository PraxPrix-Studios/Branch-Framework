# Changelog

## Unreleased

Network code is generated by Branch Studio, so these arrive with the next plugin update; the runtime in `src/` is unchanged.

- **Latest** (`Latest = true`): several sends of an event to the same recipient in one frame send only the newest. With `Delta` and a `Key`, the newest value is kept per key (so many objects fired in one frame all arrive), and struct arguments are copied, so a caller may reuse its table.
- **Hz** (`Hz = 20`): the newest value goes out at most that many times a second; the last value is never lost.
- **Lod** (`Lod = { { 50, 30 }, { 200, 5 } }`, `Event.FireFrom(position, ...)`): each player gets the event at the rate of their distance ring, nothing beyond the last ring.
- **Threshold** (with `Delta`): numbers and vectors that moved less than the threshold count as unchanged; small moves add up.
- **Predict** (`Predict = { pos = 0.25 }`, with `Delta`, `Event.At(key)` on the client): a number or vector travels with its speed, the client guesses between updates, and an update goes out only when the guess is off by more than the number. Corrections are smoothed, teleports are shown at once, and an object that is no longer fired to a player stops where it was fired last. `Event.Exact(key, on)` turns the guessing off for one object while precise movement matters (a fight). The horde tutorial goes from 10.3 KB/s to 1.9 KB/s.
- **Pack** (`Pack = true`): small numbers, enums, booleans and bounded lengths travel as bits; a 200-item inventory takes about half the bytes.
- **Smaller types in one click:** Profile (Network page) + Finish (profiler window) lists the hints under Problems; Apply rewrites the type.
- **Delta** (`Delta = true`, optional `Key`, `Event.Forget`): only the struct fields that changed since the last send travel; a changed boolean costs no bytes.
- **FireNear** (`Event.FireNear(position, radius, ...)`): sends only to players whose character is within the radius.
- **Rate limits** (`Rate = "10/s"`): extra client sends are dropped, functions answer "failed", and `OnReject` reports it.
- **Server half moved to ServerScriptService** (`BranchNetworkServer`): players no longer download the server's network code, and cannot read its checks. Existing places are moved over on the next compile.
- **Live network profiler** (Studio only): per-event traffic while you Play, with hints for smaller number types.
- **Docs website** in `docs/website`: guides, full API reference, benchmarks, unique features.
- **Problems: pick, then Solve** (Branch Studio): a click picks a problem (outlined) and a double-click opens its script; a fix (Solve, Apply, Accept) only runs from its button, so a click never changes the project.
- **Keybinds** (Branch Studio page + `Branch.Keybinds`): Roblox input actions (InputContext > InputAction > InputBinding) in a `Keybinds` folder inside the Branch module, edited on a drawn keyboard, mouse and gamepad (conflicts, presets, modifiers), and linked to controller functions: Branch Studio writes the hookup at the top of the controller's `:Start()` and adds missing functions. `Branch.Keybinds` is the folder, typed with every context and action.
- **Community** (Branch Studio): a Community page (games using Branch, people with roles, user search, profile cards), roles (Owner, Tester, VIP), My themes slots (2 free, up to 8 with game passes), image backgrounds as a game pass with a live unlock. Roles and profiles live in `community/community.json` in this repository.
- **Settings code** (Branch Studio, bottom of Settings): every setting (your look and editor settings, this place's project and network settings) as one line of letters and digits with a typo check; paste one and apply yours, the place's or both; the last 5 codes with the place each came from.
- **Themes and backgrounds** (Branch Studio, Settings > Appearance): nine themes, every color editable, a color, gradient or picture behind the window (blur, dim, tint, glass, focus, edge shade, readable text, colors from the picture), density / corners / text size, lite mode, and theme codes to share a look.
- **Segment names as you type** (Branch Studio): inside `GetSegment("…")` or a `LocateSegments({ "…" })` list the script editor suggests the segments on that script's side. Works with either Luau type solver.
- **Profiler switch:** the generated network code watches a `BranchProfile` attribute on `Branch.Network`; `false` stops the Studio traffic counters on both sides (nothing counted or published), even mid-Play. Branch Studio sets it from its Profiler switch.
- **Branch Studio tools (Studio only):** the loader publishes its report (`BranchReportServer` / `BranchReportClient` attributes on the Branch module) and `Data.Start` makes `ServerStorage.BranchDataDebug`, so Branch Studio's Branch (live) window can show every `Init` time and players' data, and its DataStores page can dry-run migrations on a real save. Neither exists in a live game.
- **Faster network code:** boolean arrays go 32 at a time and decode through a lookup table, a run of one event is read in a loop, and a player's only event of the frame is sent in a buffer of its exact size. Measured in BlinkBlox's own benchmark (see `bench/rivals`).
- **New look** (Branch Studio): new icons, page names in the rail, cards on the Overview, Settings > Appearance in tabs (Theme, Background, Colors, Layout). Midnight, Frost, Ember and Rose come with their own background picture, free for everyone.
- **Benchmarks you can run:** `bench/rivals` adds a second round (BlinkBlox, QuickNet, Warp) inside BlinkBlox's own benchmark, `lune run bench/rivals/run`. Round 1 now counts what arrives, and a fake player in its harness that was not inside Players (so Branch sent it nothing) is fixed.
- **Guards:** `Cooldown`, `Alive`, `Near` and `Owned` on client events and functions: the server drops a request that breaks one (functions answer "failed") and `OnReject` reports it.
- **Kick for forged packets:** packets no Branch client can produce (wrong remote arguments, empty, unknown events, lengths past the buffer) count as forged, and after 3 (Branch Studio, Settings › Network) the player is kicked. Bad values, rate limits and guards are only reported. `OnReject` gets a third argument, `forged`.
- **Event ids unique to each place:** the first compile gives every event a random id, kept in the place; packets made for another game or for old ids count as forged. **New ids** (Branch Studio, Settings › Network) changes them all at once.
- **Default rate:** client events and functions without a `Rate` get Branch Studio's Default rate, `3000/s`.
- **Hz and Lod traffic arrives evenly:** events with the same rate no longer all send on the same frame, and the objects of a keyed event (Delta or Latest with `Key`) are spread over the frames between two sends. Same bytes, same rate per object, no burst every few frames.
- **Anticheat** (Branch Studio, Settings › Network, on by default): every client signs a small heartbeat (about 4 bytes a second) and checks its own network module. A player is flagged only for what no real client does: a forged or repeated heartbeat, a tampered module (an unfrozen table, a swapped or hooked function), reliable packets the module never sent (a remote spy repeating calls), or 600 packets without a heartbeat. Kicked outside Studio; `OnReject` hears each finding.
- **Your own anticheat checks:** `Branch.Network.Anticheat.Check(name, fn, every?)` (client, every 5 s or `every`, rides the signed heartbeat, returns a function that takes it away), `Report(name, detail)` (client, now), `Flag(player, name, detail)` (server), `OnFlag(handler)`, `SetAction(name, "kick" | "report" | "ignore", after?)` (kick from the n-th finding) and `SetKickMessage(text)`. The docs site has an Anticheat page.
- **Ready-made checks, scores and admin panels:** `Anticheat.Use("speed" | "teleport" | "fly" | "noclip", options?)` turns on server-side movement checks (off by default; the game's own teleports, seats and spawns never count; `Pause(player, seconds)` for dashes). Every finding adds its check's weight to the player's score, and levels act once each (`SetLevel(at, "restrict" | "kick" | fn)`, `SetWeight`, `SetDecay`); `Preset("Advanced")` lets the score decide. A restricted player's refused requests count as forged and their rate limits refill at a quarter. Records for admin panels: `GetFlagged()`, `GetRecord(player)`, `OnChanged`, `Pardon(player, check?)`. Strict mode's check per send is about 20% cheaper.
- **Across servers:** `Anticheat.ShareAcrossServers(true)` shares every server's flagged players through MessagingService (only what changed, at most every 3 s, messages under 1 KB); `GetFlaggedGlobal()` and `OnGlobalChanged(userId, entry?)` give a live list of the whole game. Entries go when the player leaves, is pardoned, their server closes, or after 2.5 minutes of silence from a crashed server.
- **Ready-made checks are gentler by default:** speed needs 3 samples in a row and allows WalkSpeed × 1.75 + 4, teleport 100 studs, fly 4 s with 16 studs below, noclip 3 walls in 10 s, and each kicks at the 4th finding. Real cheats stay far beyond these.
- **Strict mode** (Branch Studio, Settings › Network, off by default): every client packet carries an 8-byte tag signed with a key of the place and the player, so a copied, repeated or hand-made packet is refused as forged; and sends work only when one of the game's scripts made them (an executor's own code or the command bar is refused).
- **Runtime tests run again:** `lune run tests/runtime.test.luau` failed 5 of 9 because its fake RunService had no `IsStudio`.

**Fixes (runtime)**

- `Data.Reset`, `Data.Send` and `Data.Peek` in `Mock` mode used the real DataStore (a Reset in a test could wipe a player's real save); they now use the Mock store. `Data.Peek` also ignored `KeyPrefix`.
- `Insert` / `Remove` on an array fired every observer of its elements with `old = nil`; now only elements that changed fire, with their old value.
- A `Timer` restarted from its own callback could no longer be stopped or paused.
- `Branch:Start({ folder })` (a table of roots) silently loaded nothing, and unknown options were ignored; both are now errors.
- The DataService remote ignores malformed client calls instead of erroring or flooding the output.
- The Data path cache no longer grows without limit with paths built at run time.
- `Util.Scythe`: a disposer that errors no longer stops the cleanup; every item is disposed and the error is raised once afterwards, as its notes describe.
- `DontSave = true` kicked every player who had never saved ("Profile load fail"); they now play on a fresh profile that is kept in memory only.
- Migrations: while an update rolls out, an older server (fewer migrations) could lower a profile's version, and the next newer server ran those migrations again (coins x10 twice). The version is never lowered now.
- Number keys: `Set(player, "friends.12345", ...)` into an empty table stored a number key, and the next UserId went in as a string: a mixed table, which DataStores refuse to save. Writing into an empty table, only `1` starts an array now. Observers of a key that did not exist yet hear it however it is stored.
- `Util.Scythe`: a sub-scope whose disposer errors is still destroyed with its parent (it stayed alive, out of reach).

**Fixes (network, with the next Branch Studio update)**

- StreamingEnabled: an Instance a client does not have arrives as nil. As a Delta `Key` it made that client drop the rest of the packet (other events included) and lose the object's state. Instance keys now travel with a number, the state is kept, and the listener hears once the Instance has streamed in. Instance fields in Delta events are sent with every update, and maps keyed by Instances leave out the missing ones.
- `Hz` with `Lod`: a `FireAll` value still waiting for its gate could arrive after a newer `FireFrom` value and stay.
- A Delta event with several string fields could error on `Fire` (a generated local shadowed a field).

## 2.0.0

A rewrite of Branch 1.

**Loader**

- `Branch:Start(roots..., options?)` replaces `StartSegments` / `StartSegmentsDeep`.
- Segment rule: `"Suffix"` (default: modules named `...Service` / `...Controller` at any depth) or `"Folders"`.
- Other loader changes:
  - `Dependencies` order `Init`;
  - frame hooks share one connection per hook type;
  - typed `GetSegment`, `GetReport`, `AwaitStart`;
  - duplicate names are errors;
  - warnings for dependencies that failed and for a `require` or `Init` that hangs.
- Utilities moved to `Branch.Util`: Scythe, ThreadReaper, Timer.

**Branch.Data** (on DataService + ProfileStore)

- Typed paths and template checks all the way down.
- NaN and infinity are refused; string keys that look like numbers (UserIds) work.
- Migrations run on a copy; leaderstats are bound to data paths.
- `Observe` fires when a parent table is replaced.
- Leave-time writes are saved.
- `Peek`, `Send`, `OnMessage`.

**Branch.Network**

- Compiled by Branch Studio from `Service.Network` declarations.
- Batching per player per frame, and one `FireAllClients` for FireAll.
- Run packing, bit-packed booleans, varint lengths, stepped numbers.
- Server validation; `OnReject`.
- Errors in listeners stay contained.

**Timer** (from Branch 1): fixed

- pause/resume;
- `IncrementTime` ordering;
- `Stop` with waiting threads;
- repeated callbacks;
- errors in callbacks.
